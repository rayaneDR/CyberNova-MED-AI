# Backend API

FastAPI + SQLAlchemy 2 + SQLite implementation of the reviewed contract in `../docs/integration-contract-v1.md`. The MVP accepts synthetic-only telemetry. It does not implement Ali's analytics, medical thresholds, diagnosis, or treatment advice. Radiation-rate and unknown-period source values stay separate from completed daily or mission dose.

## Local setup (PowerShell)

From the repository root:

```powershell
python -m venv backend/.venv
backend/.venv/Scripts/python -m pip install -r backend/requirements.txt
backend/.venv/Scripts/python -m backend.app.cli init-db
backend/.venv/Scripts/python -m backend.app.cli seed-demo
backend/.venv/Scripts/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

`seed-demo` prints the mission, astronaut UUIDs, and source-session UUIDs. It deliberately creates three distinct fictional identities (`AST-001`, `AST-01`, and `demo-crew-01`) rather than guessing aliases. Keep those generated UUIDs for the session. Register new sessions with the CLI/approved operator process for additional simulator runs; never reuse a simulator session after its process restarts.

Swagger: <http://127.0.0.1:8000/docs>

Health: <http://127.0.0.1:8000/health>

Use the returned `amina_simulator_v1` session UUID with the original unchanged simulator:

```powershell
python 'C:\Users\rayan\Downloads\simu (1).py' --mode normal --count 5 --interval 1 --astronaut-id AST-01 --mission-day 142 --endpoint 'http://127.0.0.1:8000/ingest/simulator?source_session_id=<SESSION_UUID>'
```

Read measurements with `GET /measurements?mission_id=<MISSION_UUID>&astronaut_id=<ASTRONAUT_UUID>`. The adapter stores all original packet bytes and hashes, plus canonical measurement, per-channel quality, legacy simulator check-in snapshot, and source radiation quantities in one SQLite transaction. Exact packet retries return the original receipt; changed bytes under the same source packet ID return 409.

## Configuration and security

Copy `backend/.env.example` to a server-side environment file and set `DATABASE_URL`, `FRONTEND_ORIGIN`, and (before shared hosting) a strong `WRITE_TOKEN`. Do not put write tokens in `NEXT_PUBLIC_*`. The documented development command binds only to loopback. If binding to a non-loopback interface, set `ALLOW_NON_LOOPBACK=true` and configure `WRITE_TOKEN`; the application then refuses writes without the token. CORS is limited to the configured frontend origin.

SQLite schema initialization uses SQLAlchemy metadata `create_all` and is reproducible for a fresh demo DB; it is not a migration system for an existing production database. Set a persistent `DATABASE_URL` path for restart durability.

## Tests

```powershell
backend/.venv/Scripts/python -m pytest backend/tests -q
```

The tests use the real supplied normal packet and an anomaly packet generated by Amina's unchanged CLI. `evaluation_rules.json` remains research material and is not executed.

## Scope notes

- `GET /analytics/summary` reports `not_configured`; no statistical observations are fabricated. Sensor-data quality issues are distinct from statistical alerts.
- The seed CLI is a local demo roster/session initializer, not public source-session provisioning or authentication.
- The current contract's cursor is opaque, filter-bound and receipt-snapshot-bound. First-page measurement/check-in/radiation reads return a continuation cursor when another page exists.
- Simulator source sequence/scenario/mode and all unsupported channels remain recoverable in immutable raw-ingest JSON; only the contract's three biometric channels are normalized.
- Manual check-in uses integer Samn–Perelli 1–7. Legacy 1–10 source values are retained with their original scale and are not converted.
- No radiation dose-rate integration is performed. Mission cumulative values require registered mission start and full coverage before canonical submission.
